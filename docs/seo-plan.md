# 몇프로(whatpercent.co.kr) 검색 유입 설계와 등록 절차

작성 2026-10-22. 검색엔진 등록·콘텐츠 확장의 근거와 운영 방법을 남긴다.

## 1. 문제: 콘텐츠는 많았는데 검색엔진이 못 읽었다

- '오늘의 논쟁'은 매일 5건씩 쌓여 2026-08-07부터 77일치, 약 385건이 보관돼 있었다.
- 그런데 이 내용 전부가 `index.html`의 자바스크립트 탭 안에서만 그려졌다. 크롤러가 보는
  HTML에는 논쟁 제목도 본문도 없다.
- `sitemap.xml`에 등록된 URL은 홈 하나뿐이었다. 즉 **색인될 수 있는 페이지가 1개**였다.

검색 유입이 없던 이유는 홍보 부족이 아니라 색인 대상이 없었기 때문이다.

## 2. 해결: 같은 데이터를 서버 렌더 페이지로 다시 내보낸다

`seo.py`가 `data/daily/*.json`을 읽어 자바스크립트 없이 읽히는 HTML을 만든다.
AI 호출은 전혀 하지 않는다(비용 0). 결과는 5분 캐시.

| URL | 내용 | 개수 |
|---|---|---|
| `/debates` | 날짜별 아카이브 허브(7일씩 페이지네이션) | 1 + 페이지 |
| `/debates/{날짜}` | 그날의 논쟁 5건 | 날짜 수만큼 |
| `/debates/{날짜}/{번호}` | 논쟁 1건 상세 — **롱테일 검색의 핵심** | 논쟁 수만큼 |
| `/topics` | 주제 색인 | 1 |
| `/topics/{주제}` | 주제별 논쟁 모음 | 주제 수만큼 |
| `/guide/{주제}` | 주제별 공감률 데이터 리포트 | 주제 수만큼 |
| `/sitemap.xml` | 위 전부를 자동 포함 | — |
| `/rss.xml` | 최신 50건 (네이버 제출용) | — |

주제 분류는 제목·요약의 키워드 적중 수로 자동 배정한다(8종): 축의금·결혼식 / 직장·회사 /
연애 / 가족·명절 / 이웃·아파트 / 돈·비용 / 온라인·SNS / 생활·예절.

### 왜 논쟁 1건당 페이지를 따로 두나

검색은 "축의금 10만원 기본인가요", "점심시간 1시간 다 쓰는 신입" 같은 **구체적 문장**으로
들어온다. 날짜 묶음 페이지는 이런 질의와 1:1로 맞지 않는다. 논쟁 1건 = URL 1개여야
제목·본문·질의가 일치한다. 각 상세 페이지는 쟁점 요약, 양측 입장, 집단별 예측 표,
같은 날·같은 주제의 다른 논쟁 링크, 서비스 CTA로 구성된다.

### `/guide/{주제}`가 독자 콘텐츠인 이유

남의 글 요약이 아니라 **우리가 만든 수치의 집계**다. 주제별 평균 공감률, 공감이 가장
높았던·낮았던 입장, 여론이 팽팽했던 사안, 집단별 평균 공감률 — 다른 곳에 없는 데이터라
중복 콘텐츠 위험이 없다.

## 3. 기술 요소 점검표

- 페이지마다 고유 `title` / `description` / `canonical` / OG 태그
- JSON-LD: 상세·리포트는 `Article`, 목록은 `CollectionPage`
- 내부 링크: 홈 푸터 → 아카이브·주제별, 상세 ↔ 날짜 ↔ 주제 ↔ 리포트 상호 연결
- 없는 날짜·논쟁·주제는 soft-404가 아니라 **404 + noindex**
- `robots.txt`에서 `/admin`, `/api/` 차단
- 모바일 대응(viewport, 560px 이하 레이아웃 조정)

## 4. 검색엔진 등록 절차

소유확인은 이미 끝나 있다(홈에 google-site-verification·naver-site-verification 메타 존재).
새 페이지를 알리는 작업만 하면 된다.

### 구글 서치콘솔 (search.google.com/search-console)

1. 좌측 **Sitemaps** → `sitemap.xml` 이 이미 제출돼 있으면 그대로 두고, 상태가 '성공'인지와
   **발견된 URL 수**가 수백 개로 바뀌었는지 확인한다(반영에 하루 이틀 걸린다).
2. 상단 **URL 검사**에 아래를 하나씩 넣고 '색인 생성 요청'을 누른다. 허브부터 넣으면
   크롤러가 내부 링크를 타고 나머지를 찾아간다.
   - `https://whatpercent.co.kr/debates`
   - `https://whatpercent.co.kr/topics`
   - `https://whatpercent.co.kr/guide/wedding`
   - `https://whatpercent.co.kr/guide/workplace`
3. 2~3주 뒤 **실적** 리포트에서 노출 검색어를 보고 제목·설명을 다듬는다.

### 네이버 서치어드바이저 (searchadvisor.naver.com)

1. **요청 → 사이트맵 제출**: `https://whatpercent.co.kr/sitemap.xml`
2. **요청 → RSS 제출**: `https://whatpercent.co.kr/rss.xml` ← 이번에 새로 만든 것.
   네이버는 RSS를 통해 신규 글을 더 빨리 수집한다. 매일 자동 갱신된다.
3. **요청 → 웹페이지 수집**: `/debates`, `/topics` 를 직접 수집 요청.
4. **검증 → 웹마스터 도구**로 수집 오류를 주기적으로 확인.

### 그 밖

- 빙 웹마스터도구는 서치콘솔 계정을 그대로 가져올 수 있다(Import).
- 다음(카카오)은 별도 검색등록 페이지에서 사이트 등록.

## 5. 등록 후 운영

- **자동**: 매일 0시 새 논쟁이 생기면 사이트맵·RSS에 자동 반영된다. 손댈 것이 없다.
- **월 1회**: 서치콘솔 실적에서 노출은 많은데 클릭이 적은 검색어를 찾아 해당 상세 페이지의
  `title`을 질의 문장에 가깝게 고친다.
- **분기 1회**: 주제 분류 키워드(`seo.py`의 `TOPICS`)에 새로 자주 나오는 말을 추가한다.

## 6. 다음에 해볼 만한 것

  단 사연 원문 공개 범위를 정해야 한다(개인정보·약관 검토 필요).
- 논쟁별 OG 이미지 자동 생성(제목 + 공감률 %)으로 공유 시 클릭률을 올린다.
- 투표 누적치가 쌓이면 '예측 공감률 vs 실제 투표율' 비교 페이지를 만든다. 이건 언론·커뮤니티가
  인용하기 좋은 형태의 데이터다.
